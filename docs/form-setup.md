# 상담 신청 → 구글 시트 + 슬랙 연결 방법

웹사이트 폼 → **Google Apps Script(웹 앱)** → ① 구글 시트에 한 줄 저장 ② 슬랙 채널에 알림

**토스 렌탈과 같은 시트·같은 웹 앱 주소를 함께 씁니다.** 신청서에 페이지 이름표(`page`)가 같이 오기 때문에
페이지마다 다른 탭에 쌓이고, 상단 바 누적 조회수도 따로 셉니다.

| 페이지 | `page` 값 | 신청이 쌓이는 탭 | 누적 조회수 (스크립트 속성) |
| --- | --- | --- | --- |
| 토스 렌탈 | 없음 (예전 그대로) | `신청목록` | `VIEW_COUNT` |
| 네이버 커넥트 | `connect` | `커넥트 신청목록` | `VIEW_COUNT_CONNECT` |

- 토스 렌탈 사이트는 고칠 것이 없습니다. `page` 값이 없으면 토스 렌탈로 처리되어 지금과 똑같이 동작합니다.
- 별도 서버 없이 무료로 동작하고, 슬랙 주소(웹훅)는 구글 쪽에만 저장되어 웹사이트에 노출되지 않습니다.
- 공용 코드의 원본은 이 저장소의 [`apps-script/Code.gs`](../apps-script/Code.gs) 입니다. (toss-rental 저장소의 Code.gs 는 예전 버전)

---

## 1. 토스 렌탈 시트에 합치기

1. 토스 렌탈 신청 시트를 열고 메뉴 **확장 프로그램 → Apps Script**
2. 편집기의 `Code.gs` 내용을 모두 지우고, 이 저장소의 [`apps-script/Code.gs`](../apps-script/Code.gs) 내용을 통째로 붙여넣고 저장
   - 슬랙 웹훅(`SLACK_WEBHOOK_URL`)과 토스 렌탈 누적 조회수(`VIEW_COUNT`)는 스크립트 속성에 그대로 남아 있어 다시 넣지 않아도 됩니다.
3. 편집기 상단 함수 목록에서 `setup` 선택 → **실행**
   - 새 탭 `커넥트 신청목록` 이 머리글과 함께 생깁니다. 기존 `신청목록` 탭은 건드리지 않습니다.
   - 권한 승인 창이 뜨면 승인합니다.
4. (선택) `testSubmitConnect` 실행 → `커넥트 신청목록` 에 테스트 한 줄 + 슬랙 알림이 오면 성공 (확인 후 테스트 행은 지우세요)
5. **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**
   - ⚠ "새 배포"가 아니라 기존 배포를 **수정**해야 웹 앱 주소가 그대로 유지됩니다. (주소가 바뀌면 토스 렌탈 사이트 신청이 끊깁니다)
6. 확인: 웹 앱 주소를 브라우저로 열어 `{"ok":true,"service":"paydv-rental-leads","pages":["toss","connect"]}` 가 보이면 새 코드가 적용된 것입니다.
7. 같은 웹 앱 주소를 [`public/js/config.js`](../public/js/config.js) 의 `FORM_ENDPOINT` 에 넣고 넷리파이에 반영
   (토스 렌탈의 `public/js/config.js` 에 들어 있는 주소와 같습니다)

```js
FORM_ENDPOINT: "https://script.google.com/macros/s/xxxxxxxx/exec",
```

> 순서가 중요합니다. 코드를 새 버전으로 바꾸기 전에 주소부터 넣으면, 커넥트 신청이 토스 렌탈 탭에 섞여 들어가고 조회수도 합쳐집니다.

## 2. 슬랙에 어느 페이지 신청인지 표시하기 (선택)

같은 슬랙 채널로 두 페이지 알림이 오므로, 메시지에 페이지 이름을 넣어두면 구분이 쉽습니다.

1. 슬랙 워크플로 빌더에서 기존 신청 알림 워크플로 편집 → 웹훅 변수에 `page` (텍스트) 추가
2. 메시지 첫 줄에 `page` 변수를 넣고 게시 → 예: `[네이버 커넥트] 새 상담 신청`
3. Apps Script `Code.gs` 의 `SLACK_FIELDS` 목록 맨 앞에 `'page'` 를 추가하고 저장
4. 1단계 5번처럼 **새 버전으로 배포**

> 반드시 워크플로에 `page` 변수를 **먼저** 추가하세요. 워크플로에 없는 변수를 보내면 알림이 실패할 수 있어서 기본값에는 넣지 않았습니다.

워크플로 변수 목록 (모두 텍스트, `SLACK_FIELDS` 에 넣은 것만 보냅니다)

| 변수 | 내용 | 예 |
| --- | --- | --- |
| `page` | 페이지 이름 | 네이버 커넥트 / 토스 렌탈 |
| `receivedAt` | 접수일시 | 2026-11-06 10:31:05 |
| `storeStatus` | 매장 상태 | 매장 운영 중 |
| `industry` | 업종 | 카페 · 디저트 |
| `phone` | 휴대폰 | 010-1234-5678 |
| `contactDay` | 연락 희망일 (요일) | 월요일 |
| `contactDate` | 연락 희망일 (날짜) | 2026-11-09 |
| `contactTime` | 연락 희망 시간 | 오후 14시 |
| `sheetUrl` | 시트 해당 행 바로가기 (해당 페이지 탭으로 열림) | https://docs.google.com/... |

## 3. 페이지를 더 만들 때

1. `Code.gs` 의 `PAGES` 에 한 줄 추가 (예: `kiosk: { name: '키오스크', sheet: '키오스크 신청목록', viewKey: 'VIEW_COUNT_KIOSK', color: '#fff4e5' }`)
2. 저장 → `setup` 실행(새 탭 생성) → 새 버전으로 배포
3. 새 페이지의 `config.js` 에 같은 `FORM_ENDPOINT`, `PAGE_ID: "kiosk"`

## 시트에 쌓이는 정보

| 열 | 내용 | 슬랙 알림 |
| --- | --- | --- |
| A 접수일시 | 신청이 들어온 시간 (한국 시간) | ✅ |
| B 매장 상태 | 신규 매장 준비중 / 매장 운영 중 | ✅ |
| C 업종 | 업종 선택값 | ✅ |
| D 휴대폰 | 010-1234-5678 | ✅ |
| E 연락 희망일 | 예: `월요일 (2026-11-09)` | ✅ (희망 시간과 함께) |
| F 연락 희망 시간 | 예: `오후 14시`, `언제든 가능` | ✅ |
| G 처리상태 | `신규`로 들어옴 → 상담 후 직접 변경 | 시트에만 |
| H 개인정보 동의 | `동의` (동의 시점 = 접수일시) | 시트에만 |
| I~M utm_source ~ utm_term | 광고 링크에 붙인 값 | 시트에만 |
| N 유입 경로(referrer) | 이전 페이지 주소 | 시트에만 |
| O 랜딩 URL | 처음 들어온 주소 | 시트에만 |
| P 기기 정보 | 브라우저·기기 정보 | 시트에만 |

- **G~P 열은 기록용**이라 한꺼번에 숨기기 좋게 뒤쪽에 모아두었습니다. (G열 머리글부터 P열까지 선택 → 우클릭 → 열 숨기기)
- 광고 링크에 `?utm_source=daangn&utm_campaign=connect` 처럼 붙이면 어느 광고에서 들어왔는지 함께 저장됩니다.
- 같은 번호로 여러 번 신청해도 들어온 그대로 모두 저장되고 슬랙 알림도 매번 갑니다.
- 두 탭의 열 구성은 같습니다. 탭을 지우면 그 안의 신청 기록도 사라지니 주의하세요. (탭이 없어지면 다음 신청 때 머리글과 함께 다시 생깁니다)

## 연락 희망일 (주말·공휴일 제외)

신청 화면의 연락 희망일 버튼 2개는 **주말과 쉬는 날을 건너뛴 가까운 영업일**로 바뀝니다.

| 신청하는 때 | 버튼 |
| --- | --- |
| 월~목 상담 시간 중 | 오늘 / 내일 |
| 목요일 저녁 (오늘 상담 끝남) | 금요일 / 월요일 |
| 금요일 상담 시간 중 | 금요일 / 월요일 |
| 금요일 저녁 · 토 · 일 | 월요일 / 화요일 |

- 오늘을 고르면 이미 지난 시간은 선택할 수 없습니다.
- 공휴일·회사 휴무일은 `public/js/config.js` 의 `HOLIDAYS` 에 `"YYYY-MM-DD"` 로 추가하면 건너뜁니다.

## 상단 바 누적 조회수

같은 웹 앱 주소가 페이지 방문 수도 셉니다. 따로 설정할 것은 없습니다.

- 방문자가 처음 들어올 때 1 올라가고, 같은 탭에서 새로고침하면 다시 세지 않습니다.
- 숫자는 Apps Script **프로젝트 설정 → 스크립트 속성** 에 페이지별로 저장됩니다. (토스 렌탈 `VIEW_COUNT`, 네이버 커넥트 `VIEW_COUNT_CONNECT`)
- 무료 구글 계정 기준 Apps Script 속성 읽기/쓰기 한도는 하루 약 5만 회이고 두 페이지가 함께 씁니다. 두 페이지 합쳐 하루 2만 명 정도까지는 문제없습니다.
- 숫자를 받아오는 동안에는 0부터 숫자가 올라가는 모션만 보이고, 받아오면 실제 누적 숫자에서 멈춥니다. 미리 넣어둔 가짜 숫자는 없습니다.
- 받아오지 못하면 그 기기에서 마지막으로 받은 숫자를, 그것도 없으면(`FORM_ENDPOINT` 가 비어 있는 테스트 모드 포함) 숫자 없이 "많은 사장님이 관심있게 보고 있어요" 가 보입니다.

## 코드를 고친 뒤에는

Apps Script 코드를 수정했다면 **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포** 를 해야 반영됩니다.
이렇게 하면 웹 앱 URL은 그대로 유지됩니다. ("새 배포"를 다시 만들면 URL이 바뀌니 주의)
